# ВМаксате Messenger

Минимальный мессенджер на Node.js + Express.

## Что умеет
- поиск собеседника по `user id` или имени;
- сохранение профиля пользователя;
- регистрация с проверкой user ID (3–20 латинских букв и цифр) и пароля (не менее 6 символов, латинские буквы и цифры, минимум по одной букве и цифре);
- короткое описание «О себе» в профиле;
- открытие диалога по выбранному собеседнику;
- отправка и просмотр сообщений в текущем чате.
- редактирование отправленных текстовых сообщений;
- индикатор набора текста в реальном времени;
- аудио- и видеозвонки между двумя пользователями.

## Локальный запуск

```bash
npm install
npm start
```

Откройте в браузере:

```text
http://localhost:3000
```

## Деплой на Railway
1. Загрузите проект в GitHub.
2. В Railway создайте новый проект из GitHub-репозитория.
3. Укажите команду запуска:

```bash
npm start
```

4. Порт задайте через переменную окружения `PORT`.
5. Задайте секреты `ADMIN_PASSWORD` и `ADMIN_SESSION_SECRET`. Сгенерировать второй можно командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`. Без обоих секретов админ-панель будет отключена.
6. Для хранения в Firestore задайте переменную окружения `FIREBASE_SERVICE_ACCOUNT` со значением содержимого JSON-ключа Firebase Service Account.
7. Чтобы полностью отказаться от Firebase, задайте `STORAGE_MODE=local` и подключите постоянный Volume Railway к папке, указанной в `DATA_DIR` (например, `/data`). Тогда добавьте также `DATA_DIR=/data`.
8. Без Firebase и без постоянного Volume данные сохраняются только до следующего перезапуска Railway.

## Firebase
- В Firebase Console создайте проект и Service Account.
- Скачайте JSON с ключом.
- В Railway откройте Project → Variables и добавьте переменную `FIREBASE_SERVICE_ACCOUNT`.
- Значение переменной — это именно текст JSON, который вы скачали из Firebase.
- После этого сервер будет читать/записывать пользователей и чаты через Firestore.
- Пароли пользователей хранятся в виде bcrypt-хешей. Старые пароли в открытом виде автоматически хешируются после успешного входа.
- Сервер кэширует чтения Firestore на 15 секунд. Интервалы можно изменить переменной `FIRESTORE_CACHE_MS`.

## Supabase
- Создайте проект на [Supabase](https://supabase.com), откройте SQL Editor и выполните содержимое `supabase-schema.sql`.
- Если проект Supabase уже подключён, повторно выполните этот SQL-файл, чтобы добавить поля и ограничения, нужные для статусов доставки и стикеров.
- Повторное применение добавляет также поле отметки редактирования сообщений.
- Для поля профиля «О себе» SQL-файл добавляет колонку `about` (до 160 символов на уровне приложения).
- SQL-файл также создаёт функцию `get_chat_list`, используемую для получения последнего сообщения каждого диалога и сортировки списка чатов без загрузки всей истории переписки.
- Повторное выполнение также включает таблицы сообщений и сигналов звонка в Supabase Realtime; приложение получает новые события через push-подписку, а не частый опрос базы.
- Доставка Realtime-событий учитывается в отдельной квоте Supabase Realtime.
- В Railway задайте `STORAGE_MODE=supabase`, `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` из настроек проекта Supabase.
- Ключ `SUPABASE_SERVICE_ROLE_KEY` используется только на сервере Railway: не добавляйте его в клиентские файлы и не публикуйте.
- Старые данные Firestore не переносятся автоматически: после переключения пользователям нужно зарегистрироваться заново, либо данные можно импортировать отдельно.

## Звонки
- Звонки используют WebRTC: после выбора собеседника доступны кнопки аудио- и видеозвонка.
- Сервер передаёт только служебные сигналы соединения; аудио и видео идут напрямую между браузерами.
- Входящий вызов, пропущенный пока пользователь был не в сети, можно принять в течение 5 минут после его начала.
- Для рабочих сетей с NAT или строгим firewall добавьте свой TURN-сервер в `ICE_SERVERS` в `public/app.js`. Без TURN некоторые пользователи смогут обмениваться сообщениями, но не смогут установить медиа-соединение.

## API

### Пользователи
- `GET /api/users?search=...` — поиск пользователей.
- `POST /api/users` — создать пользователя.

### Чат
- `GET /api/chat?me=...&other=...` — получить сообщения между двумя пользователями.
- `POST /api/chat` — отправить сообщение.
